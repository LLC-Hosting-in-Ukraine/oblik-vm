# Облік ВМ — для розробників

Як зібрати програму, як влаштований код і яких правил обліку дотримується ядро.
Для користувачів — [README](../README.md).

## Середовище

* Цільовий ПК: Windows, **без прав адміністратора, без інтернету**, запуск з флешки, один
  користувач. Нічого не встановлюється — лише `OblikVM.exe`. Тому: без CDN, без важких
  фронтенд-фреймворків, без зовнішніх сервісів.
* Розробка: Python 3.13. Стек — Flask (127.0.0.1, сам відкриває браузер), SQLite через `sqlite3`
  (без ORM), docxtpl (Word), reportlab (PDF), openpyxl (Excel), PyInstaller (один .exe).
* Інтерфейс, документи, повідомлення й коментарі в коді — **українською**.

### Windows

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m pytest -q          :: тести
.venv\Scripts\python run.py               :: запуск; дані — у dev_data\
.venv\Scripts\python tools\demo_core.py   :: демо ядра обліку на тимчасовій базі
build.bat                                 :: тести + збірка dist\OblikVM.exe
```

### macOS / Linux

```sh
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python run.py
```

`OblikVM.exe` збирається **лише на Windows** (PyInstaller не робить крос-збірку) — локально
`build.bat` або в CI (`.github/workflows/build.yml`). Код має лишатися кросплатформним: шляхи
через `pathlib`, без Windows-only викликів (крім `instance.py`, де є запасний варіант).

Змінні середовища: `OBLIK_ROOT` (папка даних), `OBLIK_LOCAL` (робоча копія бази),
`OBLIK_NO_BROWSER=1` (не відкривати браузер).

## Інваріанти обліку (не порушувати)

* Майно рухається **тільки документами**; залишки рахуються з `movements`, вручну не редагуються.
* `movements` — подвійний запис «звідки → куди». Ключ залишку: (місце, номенклатура, поштучна
  одиниця, категорія, ціна).
* Проведений документ незмінний (перевірка в коді **і** тригерами БД). Виправлення — сторно
  (дзеркальний документ `doc_type='storno'`, `reversal_of_id`); сторно заборонене, якщо майно
  вже рушило далі.
* Від'ємний залишок неможливий ні на дату операції, ні пізніше (`balances.available`).
* Видане особі рахується за нею і в залишках **того місця обліку, яке видало** (пп. 11, 16
  розд. V Інструкції: з обліку не знімається). Місце особи — пара (особа, хто видав).
* Майно, передане підприємству на ремонт, з обліку **не знімається** (п. 4 розд. I).
* Чернетки не видаляються — анулюються (нумерація без пропусків). Нумерація — по роках.
* **Наряд** (`order`) — розпорядчий документ: «проведено» = підписано й зареєстровано, руху
  немає (тригер `movements_not_for_orders`), не сторнується. Виконання рахується з проведених
  і не сторнованих документів з `order_id` та ручних відміток (`order_marks`).
* **Акт якісного стану** (`condition`): рядки без напряму списуються (місце → «Списано»), рядки
  `direction='in'` оприбутковуються («Оприбутковано за актом» → місце). Маршрут рядка —
  `documents.route()`; ним користуються перевірка залишків, проведення й сторно.
* **Примірники** друкованих документів: `documents.copies()` — список у `extra_json["copies"]`
  або за замовчуванням сторони документа.

## Домовленості в коді

* Гроші — **копійки** (INTEGER), кількість — **тисячні** (INTEGER, `qty_m`), дати — ISO `РРРР-ММ-ДД`.
* Сортування — `ORDER BY name COLLATE UK`; пошук — `ulower(col) LIKE ?`.
* Сервісні функції не комітять — комітить веб-запит (`teardown` у `web/__init__.py`), після
  чого база одразу пишеться на флешку.
* Помилки для користувача — зрозумілою мовою, з номером рядка документа.
* Нормативних вимог не вигадувати: якщо чогось немає в наказі — позначати як припущення.
* Кожна нова сторінка — з підказками для новачків: блок «Що це за сторінка» (`help.PAGE_HINTS`)
  і значки «?» біля термінів (`help.GLOSSARY`, макрос `hint()` з `_help.html`).

### Міграції

* Нова міграція — новий файл `oblik/schema/NNN_*.sql`; застосовані не змінюються.
* Перебудова таблиці (SQLite не вміє більшість ALTER) — файл починається з
  `-- foreign_keys: off`, і в ньому треба **відтворити тригери й індекси** старої таблиці.
* Тест: база попередньої версії з даними → `db.migrate` → дані на місці, тригери діють.

### Шаблони Word

* `.docx` не правити руками — лише `tools/make_docx_templates.py`, і генерувати **лише змінений**
  шаблон (`make_docx_templates.py act_oz.docx`): .docx містить час створення, і перегенерований
  без змін файл програма сприйме як нову версію стандартного шаблону.
* Ширини колонок PDF і Word — однакові (спільні константи в `pdf_out`).
* Перевірка в самому Word (Windows): `cscript //nologo tools\word_check.vbs файл.docx` — кількість
  сторінок (кладе PDF поруч — такі файли в `.gitignore`).

### Правила використання

При першому запуску (для кожної бази) — сторінка `/terms`: програма допоміжна, не офіційна,
експертиз (КСЗІ тощо) не проходила; дані лише локально; інформацію з обмеженим доступом не
вносити. Змінили суть правил — збільште `TERMS_VERSION`. Не прибирати.

## Тести і дані

* Перед комітом — `pytest -q` зелений; для інтерфейсу — запустити й переглянути сторінки.
* У тестах, прикладах і демо — **лише вигадані дані** (частина «А0000», «Коваль Олена»,
  «SN-001»). Реальних документів, ПІБ, номерів частин у репозиторії бути не може.

## Випуск

1. Версія — `oblik/__init__.py` (`__version__`) і заголовок у `CHANGELOG.md`.
2. Тег `vX.Y.Z` → GitHub Actions збирає `OblikVM.exe` на Windows і створює реліз з exe та
   `SHA256SUMS.txt`.
